# Retail Banking Console — Phase 0

Frontend-only React 18 + TypeScript console over two entities and one foreign key.

## Entities

| Entity | Fields |
| --- | --- |
| `Customer` | `id`, `firstName`, `lastName`, `email`, `phone` |
| `Account` | `id`, `accountNumber`, `customerId` → `Customer.id`, `balance`, `status` |

`id` is generated by the store; every other field is entered by the user.

## Scope

Plain create / get / list / update / delete for both entities, and nothing else.
No search, no filters, no sorting, no theming, no field validation — those
belong to later phases.

The single FK, `Account.customerId → Customer.id`, is enforced on account create
and on reassignment: an account cannot point at a customer that does not exist.
Deleting a customer is a plain delete, so any accounts they held remain and show
their owner as "Unknown".

## Layout

```
src/
  types.ts                  entity types
  lib/id.ts                 per-prefix monotonic ids (resettable in tests)
  lib/useHashRoute.ts       minimal hash router (no router dependency)
  lib/usePagination.ts      page slicing, clamped when the list shrinks
  data/repository.ts        generic immutable in-memory table
  data/bankingStore.ts      domain operations + FK guards
  state/BankingContext.tsx  React provider exposing the store as an API
  components/               CustomerForm, AccountForm (dialog bodies)
  pages/                    CustomersPage, AccountsPage
  ui/                       Sidebar, PageHeader, Pagination, RowActions, Modal
  App.tsx                   sidebar shell + route switch
```

## Shell

Sidebar navigation over `#/customers` and `#/accounts`, each page a table card
with a `+ Add` dialog, per-row edit/delete actions, and pagination at 10 rows a
page. Routing and pagination go beyond the original Phase 0 list; the domain
layer underneath is unchanged.

State lives in memory only; a reload starts from an empty store.
